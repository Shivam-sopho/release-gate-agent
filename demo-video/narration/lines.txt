s1|This is release-gate-agent: an AI agent that tests what actually ships. It compares two compiled Android builds, tests the risky user journeys on a real emulator, and never ships a release without a human saying yes.
s2|The worst release bugs don't crash. Here, version two renamed a settings file with no migration. Fresh installs work, so a normal smoke test passes. But every existing user is silently logged out the moment they update.
s3|The agent starts from the compiled diff, not the source code. It plans which journeys the change puts at risk, runs them on both builds, and only reaches a verdict with device evidence. The final step is a human approval gate, enforced by the harness itself.
live1|Here is a real run. We drop in the old and new builds and start the check. The diff shows only one class changed, AuthManager, and a preferences file was renamed.
live2|On the emulator, the agent logs in on version one, upgrades in place to version two, and relaunches. The user is back on the sign-in screen. Then it runs a fresh install as a control, to prove the bug only hits people who update.
live3|Regression detected, with evidence. The agent cannot ship anything by itself, so a human reviews the verdict and decides. The report includes the results table, screenshots, the root cause, and a suggested fix in code.
live4|And this is the report it wrote: what changed, every journey with its result, the screenshots, and the fix.
s4|Every run is traced in neatlogs. Reading the first traces, we found three problems: the agent looked at the screen before the app had loaded, it spent an extra step after every tap, and it had no way to say it couldn't test. Version two fixes all three. Across eight real runs: same accuracy, thirty-eight percent fewer turns, and twenty-two percent lower cost.
s5|We also injected failures. The emulator went offline during install, and dropped a tap later on. The agent waited for the device, retried, re-checked the screen, and still reached the correct verdict, documenting both recoveries in its report.
s6|Entire is part of the agent itself. The binary diff tells us what changed; entire-graph tells us what it touches. AuthManager is used by the splash, login and dashboard screens, so those are the journeys to test. The agent also posts its verdict and evidence to an Entire Trail, right next to the code review, where a human approves. And every coding session on this repo is captured as a checkpoint.
s7|Because neatlogs gives us the real cost per check, we planned the business in cfo.ai. Twenty-one cents per check on the demo apps, budgeted at one dollar ten for real apps. A team plan at one ninety-nine a month per app, and break-even in month six.
